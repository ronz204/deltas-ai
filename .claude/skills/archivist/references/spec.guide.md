# Writing specs and designs

Loaded by archivist when writing `deltas/<slice>.spec.md` and `<slice>.design.md`. The living-contract rules, verification tags and EARS forms are in `artifacts/spec.template.md` and `artifacts/design.template.md`; this file holds the procedure around them. Step numbers below refer to archivist's own SKILL.md.

A slice is a cohesive capability (e.g. a `checkout-flow` slice), not one source file: pick the grain the way a bounded context would be picked, not by file structure. Slices live as flat files directly under `deltas/` at the project root, `<slice>.spec.md` and optionally `<slice>.design.md`, never in a per-slice subfolder. Favor fewer, right-sized slices: if two specs keep changing together for the same reason they are one bounded context, and merging them costs less upkeep than maintaining the pair in lockstep. When the repo is genuinely split into multiple independently-deployable services, read `references/spec.layout.md` before placing the files.

- **Reconcile conflicts explicitly, don't pick a side quietly.** If writing a spec or design surfaces a mismatch between the real implementation and an existing `.claude/docs/*` claim, fix the doc in the direction the code or decision supports and update the spec or design in place to match. No separate record of the resolution is kept beyond the corrected text.
- **Retiring a slice is deletion, not archival.** When a slice's implementation is confirmed intentionally removed (a `sentinel` `Gone` verdict, or the user says so), delete its `<slice>.spec.md` and `<slice>.design.md` outright. This system keeps no history layer; git history is the record of what the contract used to say.
- **Specs and designs usually arrive from `specifier`**, which does the information-gathering and the user Q&A. Treat that handoff as vetted input but still verify it against the code per Step 0: `specifier` investigates and asks, `archivist` writes. Writing directly with no handoff is only valid when Step 0's gate confirms the content is already fully known, not because a trigger phrase fired first.
- **A `[none]` tag is recorded, never fixed here.** List the invariant under Deferred / Open questions as a testing gap, because that list tells QA where tests are missing. This skill never writes the missing test.
- **A claim with no observable response isn't an invariant yet.** If it can't be written in an EARS form a test or grep can observe, send it back to `specifier`. An older spec keeps its current wording until it is next touched. The same forms suit a design's States (While ...) and Interactions (When ...).
